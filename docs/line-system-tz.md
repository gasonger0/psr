# ТЗ: Перенос правил линий с ID/названий на настраиваемые поля

Дата: 2026-10-04
Коммит: e87b169 «feat: перенос правил линий с ID/названий на настраиваемые поля»

## 1. Постановка задачи

Правила использования линий были зашиты в код:

| Критерий | Старая реализация |
|---|---|
| Линия «Сборка ящиков» | `line_id == 37` (~25 мест в `ProductsPlanController`, `Util`) |
| Продукция «телевизор» | поиск подстроки «телевизор» в названии (причём на бэке искали в названии **линии** — баг) |
| Возвратные массы | 4 паттерна названий линий: «непрерывная линия», «шоколадная линия», «полуавт», «shot» |
| Участие в датировании | захардкоженные списки линий по категориям: зефир `[14, 17, 18, 20, 24, 25, 41, 51]`, конфеты `[31]`, суфле `[20]` |
| Дефолты линий | `config/lines_defaults.php` (дублировался с таблицей `lines_defaults`) |

Добавление новой линии с особым поведением требовало правки PHP/JS. Линия 51 существовала только в БД и в массивах кода.

**Цель:** перенести правила в настраиваемые поля, редактируемые в интерфейсе (форма линии / карточка продукции), без правки кода.

## 2. Новая схема данных

Добавленные поля:

| Таблица | Поле | Тип | Назначение |
|---|---|---|---|
| `lines` | `return_type` | tinyint, nullable | Правило возвратных масс: 1 — непрерывная линия, 2 — шоколадная линия, 3 — линия-полуавтомат, 4 — one-shot; null — не участвует |
| `lines` | `use_dating` | boolean, default false | Учитывать линию в датировании |
| `products_dictionary` | `televisor` | boolean, default false | «Телевизор»: добавлять штуки в расчёт длительности сборки ящиков |

Роль линии: в `lines.type_id` добавлено значение **3 — «Сборка ящиков»** (ранее линия 37 имела `type_id = 2` и выделялась только по ID).

## 3. Миграции (разделены на два этапа)

### 3.1 Подготовительная: `2026_08_31_000000_add_line_rule_fields.php`

Обратно совместима со старой версией приложения: только добавляет столбцы и заполняет их, существующие данные не меняет. Может применяться заранее, прод продолжает работать.

Заполнение по данным старой версии:
- `return_type` — по паттернам названий в **том же порядке проверок**, что и старый код (поэтому «непрерывная линия» имеет приоритет над «шоколадной»): «непрерывная линия» → 1, «шоколадная линия» → 2, «полуавт» → 3, «shot» → 4;
- `use_dating` — `true` для старых эталонных линий `[14, 17, 18, 20, 24, 25, 31, 41, 51]`;
- `televisor` — `true` для продукции с «телевизор» в названии.

### 3.2 Переключающая: `2026_08_31_000001_set_crate_lines_type3.php`

Переводит линию 37 на `type_id = 3`. **Разрывает совместимость** со старой версией (она не понимает `type_id = 3`: распределение листов отчёта, время работы по умолчанию, подстраховка заказа). Применяется только вместе с деплоем новой версии. Откат — `migrate:rollback` (вернёт `type_id = 2`).

## 4. Изменения бэкенда

### 4.1 Модели
- `app/Models/Lines.php` — `return_type`, `use_dating` добавлены в `$fillable`.
- `app/Models/ProductsDictionary.php` — `televisor` добавлен в `$fillable`.

### 4.2 `app/Util.php`
- `calcDuration()`: сборка ящиков определяется по `$slot->line->type_id == 3` вместо `line_id == 37`; «телевизор» — по `$product->televisor` вместо поиска в названии. Попутно исправлен баг: раньше подстрока «телевизор» искалась в названии **линии**, а не продукции.
- `createDate()`: `case 3` — сборка ящиков работает по графику упаковки (8:00–20:00).
- `calcReturnMass()`: разбор названия заменён `match` по `return_type`: 1 → фикс. 25, 2 → 0.015 (зефир) / 0.00405 (суфле), 3 → 0.025, 4 → 0.005, null/прочее → не участвует. Попутно исправлен `UnhandledMatchError` («шоколадная линия» + категория «конфеты» — раньше падала, теперь корректно не участвует).

### 4.3 `ProductsPlanController`
- Все проверки `line_id == 37` заменены на проверку роли линии `type_id == 3` (методы `update`, `change`, `delete`, `processPacks`, `validateAndFixChildPlans`).
- ID линии сборки ящиков берётся динамически (`$plan->slot->line_id`), а не константой 37.
- Пересчёт планов после сдвигов выполняется по **всем** линиям с `type_id = 3` (`Lines::where('type_id', 3)`), а не только для 37.
- Запросы через `whereHas('slot.line', ...)` (раньше — `whereHas('slot', ...)`).

### 4.4 `ProductsDictionaryController`
- В расчёте бэклога (страховка заказа) линия сборки ящиков (`type_id = 3`) учитывается как упаковка: `$index = $plan->line->type_id == 3 ? 2 : $plan->line->type_id`.

### 4.5 `TableController` (отчёт)
- Распределение по листам: линия с `type_id = 3` попадает на лист упаковки (как раньше линия 37).
- Датирование: проверка `$line['use_dating']` вместо захардкоженных списков по категориям.
- Итоги отчёта: строки итогов формируются и для `type_id = 3`.

### 4.6 Изменение поведения (осознанное, задокументировано)
Датирование теперь привязано к **линии**, а не к категории продукции: раньше линия 20 датировалась только по суфле, 31 — только по конфетам; теперь датируется вся продукция, изготовленная на линиях с флагом `use_dating`.

## 5. Дефолты линий

- Данные из `config/lines_defaults.php` перенесены в `LinesDefaultsSeeder` (константа `DEFAULTS`) — сидер стал источником правды.
- `Util::getDefaults()`: чтение из таблицы `lines_defaults`; если БД ещё не засеяна — fallback на старый конфиг.
- `config/lines_defaults.php` оставлен временно как fallback, подлежит удалению после стабилизации.

## 6. Изменения фронтенда

Реестр линий — существующая доска «Рабочие» (`components/boards/workers/board.vue`), редактирование — `components/common/lineForm.vue`.

- `lineForm.vue`: роль линии — радиокнопки «Варка / Упаковка / **Сборка ящиков**»; дропдаун «Возвратные массы» (1–4, с очисткой = «не участвует»); чекбокс «Учитывать в датировании».
- `store/dicts.ts`: справочник `lineReturnTypes` с подписями правил.
- `store/lines.ts`: новые поля в типе `LineInfo` и в дефолтах новой линии; `return_type` и `use_dating` отправляются на бэк всегда (в т.ч. `null`), чтобы очистка дропдауна сохранялась.
- `modals/plan.vue`: расчёт длительности сборки ящиков по `type_id == 3` и `product.televisor` вместо `line_id == 37` и поиска в названии.
- `modals/products.vue`: вкладка «Справочная информация» — новое поле «Телевизор» (чекбокс с подсказкой «Добавлять шт в расчёт длительности»), добавлен компонент tooltip для подсказок полей.
- `store/products.ts`: поле `televisor` в типе и дефолтах.
- Пересобраны бандлы (`public/build/*`).

## 9. Что осознанно осталось на ID/названиях (кандидаты на следующие итерации)

| Место | Критерий | Комментарий |
|---|---|---|
| `TableController` | Массивы `[8, 9, 10, 11, 12]` и `[14, 17, 18, 20, 24, 25, 41, 51]`, `31`, `20` | Правила накопления `z/s/k` (возвратные массы, итоги по категориям) |
| `modals/plan.vue` | Паттерн «one shot» в названии и `line_id == 31` | Опции упаковки конфет |
| `ProductsPlanController::fixFisMachineConflicts` | Паттерн «фис машина» в названии (`LOWER(title) LIKE '%фис машина%'`) | Конфликты планов на фис-машинах |
| Слоты | `type_id` 1–5 (варка/упаковка/глазировка/обсыпка/опудривание) | Магические числа в `switch` |

Кандидаты на перенос в настраиваемые поля по той же схеме: роль линии / флаг (`boiling`, `reference_pack`, `one_shot`, `fis_machine`) или отдельный `return_type`-подобный справочник правил накопления.
