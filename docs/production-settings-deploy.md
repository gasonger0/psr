- Интервал упаковки при постановке плана: было зашитые +10 мин, стало настройка «Интервал упаковки» = 15 мин.

```bash

mysqldump -u <user> -p <имя_БД> > backup_$(date +%F).sql
```

### Шаг 1. Деплой кода

`git pull` (ветка main) или обычный процесс деплоя. Артефакты фронтенда (`public/build/*`) уже закоммичены в репозитории — пересборка на проде не нужна.

### Шаг 2. Миграции и сиды (порядок важен)

```bash
# docker: docker exec psr-www-1 php artisan migrate
php artisan migrate
# создаст hardwares/return_types/settings; удалит мёртвые колонки lines/lines_defaults

# docker: docker exec psr-www-1 php artisan db:seed --class=LinesDefaultsSeeder
php artisan db:seed --class=LinesDefaultsSeeder
# дефолты линий в таблицу (идемпотентно)

# docker: docker exec psr-www-1 php artisan db:seed --class=ProductionSeeder
php artisan db:seed --class=ProductionSeeder
# оборудование (ID 1–6), режимы возвратных масс (ID 1–4), настройки (интервалы, производительность ЗМ) — идемпотентно

php artisan config:clear
# сбросить кэш конфигов — файл config/lines_defaults.php удалён из кода
```

### Шаг 3. Проверка после обновления

1. «Реестры» → «Производство»: окно открывается на весь экран, 4 вкладки; в колонке «Тип» видны названия («Варка», «Упаковка», «Сборка ящиков»), а не цифры.
2. Вкладки «Оборудование» и «Возвратные массы» содержат записи (6 и 4 соответственно).
3. «Постоянные величины»: интервал варки = 10, интервал упаковки = 15, производительность ЗМ = 143.5 и 287.
4. Поставить новый план упаковки: к его окончанию прибавляется интервал упаковки (15 мин по умолчанию).
5. Сформировать отчёт за смену с упаковкой: присутствует лист «Экспорт»; названия оборудования полные («Завёрточная машина №1»).
6. Доска «Компания»: форма линии больше не содержит регистровых полей (тип, возвратные массы, датирование) — они в окне «Производство».

## Откат

- **Откат кода на старую версию**: безопасен. Старый код новые таблицы игнорирует; удалённый конфиг вернётся вместе со старыми файлами; поведение вернётся к хардкоду (интервал упаковки снова +10).
- **Откат миграций**: `php artisan migrate:rollback --step=2` — вернёт колонки `lines_defaults`, удалит новые таблицы.

## Примечания

- Обе миграции обратимы; колонки `lines` при откате миграции-чистки не восстанавливаются ею намеренно — они принадлежат более ранней миграции `2025_02_13_092041_add_day_column.php` (та уже удалила их из `lines` и перенесла в `line_extra`/`lines_extra`).
- Тестовый каркас: `tests/TestCase.php` исправлен под Laravel 11 (тесты запускаются на чистой БД; повторный прогон без очистки БД может падать — известный предсуществующий дефект тестов, на прод не влияет).
