# Дизайн: Окно «Производство» — редактируемые правила и справочники

Дата: 2026-10-04
Статус: согласовано, ожидает контрольной проверки перед реализацией

## 1. Контекст и цель

Правила работы линий исторически зашиты в код (ID линий, паттерны названий, магические числа). Часть уже вынесена в настраиваемые поля ([docs/line-system-tz.md](../../line-system-tz.md), коммит e87b169): роль линии `type_id = 3`, `lines.return_type`, `lines.use_dating`, `products_dictionary.televisor`.

Остаются нередактируемыми:
1. Интервалы времени: варка — 10 мин, упаковка — 15 мин (в коде сейчас всё `addMinutes(10)`, в т.ч. для упаковки).
2. Нормы расчёта возвратных масс зефирной массы (захардкожены в `Util::calcReturnMass`: 25 / 0.015 / 0.00405 / 0.025 / 0.005).
3. Оборудование — справочник, зашитый в `dicts.ts` (`hardwares`, `packHardwares`).
4. Производительность ЗМ в fallback-логике `plan.vue`: 143.5 / 287.

**Цель**: окно «Производство» в реестрах с редактированием этих параметров без правки кода и без магических чисел.

## 2. Принятые решения (сводка)

| Вопрос | Решение |
|---|---|
| Возвратные массы: формула или дропдаун | Справочник режимов (таблица с названием, типом формулы, коэффициентами) + дропдаун в линии. Свободные формулы (eval) отклонены |
| Поле «Телевизор» в таблице линий | Убрано — это свойство продукции, редактируется в карточке продукции |
| Новая вкладка «Линии» vs доска «Компания» | Реестр в «Производство» → «Линии»; доска «Компания» остаётся операционным экраном (сменные значения + расстановка сотрудников). lineForm на доске сокращается до сменных полей |
| Множитель длительности у оборудования | Не нужен — производительность задаётся в слотах реестра продукции. Поле исключено |
| Производительность ЗМ (143.5/287) | Включена в «Постоянные величины» |
| Bulk-update линий | Один эндпоинт `/lines/bulk-update`, сам раскладывает поля: правила → `lines`, шаблон смены → `lines_defaults` |
| Избыточность схемы | Убрать мёртвые колонки: `lines.workers_count/started_at/ended_at`, `lines_defaults.title/started_at/ended_at` |
| Хранение настроек | Отдельные таблицы (подход A). Конфиг-файл и универсальный EAV-справочник отклонены |

## 3. Архитектура и схема БД

### 3.1 Структура данных линий (после чистки)

Три уровня с разными жизненными циклами, без пересечений полей:

| Таблица | Поля | Жизненный цикл |
|---|---|---|
| `lines` | title, color, type_id, return_type, use_dating | сущность и правила, редко |
| `lines_defaults` | line_id, perfomance, workers_count, prep_time, after_time | шаблон смены («Сохранить как значение по умолчанию») |
| `lines_extra` | сменные значения (started_at, ended_at, prep_time, workers_count, master, engineer, детектор, extra_title, down_*) | факт конкретной смены (date + isDay) |

### 3.2 Новые таблицы

**`hardwares`** — оборудование:

| Поле | Тип | Назначение |
|---|---|---|
| `hardware_id` | PK, autoincrement | сохраняет текущие значения 1–6, ссылки из слотов продукции не ломаются |
| `title` | string | короткое название («ЗМ №1», «Мондомикс») |
| `full_title` | string, nullable | полное название («Завёрточная машина №1») |
| `type` | tinyint | 1 — варка, 2 — упаковка |

Сид (с явными `hardware_id` 1–6, чтобы ссылки из `products_slots.hardware` сохранились): Торнадо (1), Мондомикс (2), Китайский Аэрос (3), ЗМ №1 (4), ЗМ №2 (5), ЗМ №1 и №2 (6).

**`return_types`** — режимы возвратных масс:

| Поле | Тип | Назначение |
|---|---|---|
| `return_type_id` | PK, autoincrement | текущие режимы сохраняют ID 1–4 (совместимость с `lines.return_type`) |
| `title` | string | «Непрерывная линия»… |
| `formula_type` | enum: `fixed` \| `coef` | фикс. значение или коэффициент от суммы |
| `fixed_value` | decimal, nullable | для `fixed` |
| `coef_z` / `coef_s` / `coef_k` | decimal, nullable | коэффициенты для зефира / суфле / конфет |

Сид (сохраняет текущее поведение): 1 — fixed 25; 2 — coef z=0.015, s=0.00405, k=null; 3 — coef z=0.025; 4 — coef z=0.005. Новые режимы добавляются из UI, дропдаун в линии подхватывает автоматически. `coef_k = null` означает «категория не участвует» (как сейчас).

**`settings`** — постоянные величины (key-value):

| key | value (сид) | Назначение |
|---|---|---|
| `interval_boil` | 10 | интервал варки, мин |
| `interval_pack` | 15 | интервал упаковки, мин |
| `zm_perfomance` | 143.5 | производительность одной ЗМ |
| `zm_perfomance2` | 287 | производительность двух ЗМ |

### 3.3 Миграция-чистка

Удаляются мёртвые колонки (обоснование — в таблице 3.1 и трассировке в ходе брифа):

- `lines`: `workers_count`, `started_at`, `ended_at` — затеняются `lines_extra` при `array_merge` в `LinesController::get`, `getOrInsert` всегда создаёт extra;
- `lines_defaults`: `title` (игнорируется при создании extra — не в `$fillable`), `started_at`, `ended_at` (`Util::createDate` всегда перезаписывает по графику роли).

Сопутствующие правки: убрать эти поля из `Util::setDefault` allowed-списка и из `LinesDefaultsSeeder` (оставить `line_id`, `perfomance`, `workers_count`, `prep_time`, `after_time`); `config/lines_defaults.php` удаляется вместе с fallback в `Util::getDefaults` (после засеивания БД).

## 4. Бэкенд

### 4.1 Модели и API

- Новые модели: `Hardware`, `ReturnType`, `Setting` (с `Setting::get(string $key, $default = null)`; кэш на запрос — значение читается редко, per-request memory достаточно).
- Новые маршруты в `routes/api.php` (по образцу существующих контроллер-групп):
  - `/hardwares` — get / create / update / delete;
  - `/return_types` — get / create / update / delete;
  - `/settings` — get (все ключи) / update (список);
  - `/lines/bulk-update` — POST: массив `line_id` + поля для массового применения.
- Защита от удаления со ссылками:
  - оборудование, используемое в `products_slots.hardware` — удаление запрещено с сообщением «используется»;
  - режим возвратных масс, на который ссылается `lines.return_type` — аналогично.

### 4.2 Bulk-update линий

Один эндпоинт, раскладка по таблицам на бэке:

| Поля | Таблица |
|---|---|
| Наименование (title), Тип (type_id), Возвратные массы (return_type), Учитывать в датировании (use_dating), Цвет (color) | `lines` |
| Производительность (perfomance), Подготовительное время (prep_time), Заключительное время (after_time), Рабочие (workers_count) | `lines_defaults` (updateOrCreate по line_id — тот же механизм, что `Util::setDefault`) |

### 4.3 Замена магических чисел

| Место | Сейчас | Станет |
|---|---|---|
| `ProductsPlanController` строки 226, 301, 742, 782, 950 (упаковка/ящики) | `addMinutes(10)` | `Setting::get('interval_pack')` |
| `ProductsPlanController` строка 952 (варка) | `addMinutes(10)` | `Setting::get('interval_boil')` |
| `Util::calcReturnMass` | match по захардкоженным 1–4 | чтение `return_types` из БД (одна выборка на запрос, далее по коллекции); `coef_k` участвует, если задан |
| `plan.vue` fallback производительности ЗМ | `143.5` / `287` | `zm_perfomance` / `zm_perfomance2` из настроек |
| `Util::calcDurationForZM` | мёртвый код с `$hardware == 3 → ×2` | удалить |

### 4.4 Изменение поведения (осознанное)

- Упаковка при постановке плана получает **+15 мин** вместо текущих +10 (значение 15 теперь в БД, редактируется).
- Возвратные массы: поведение идентично текущему (те же значения, `k` не участвует, пока `coef_k` не задан).

## 5. Фронтенд

### 5.1 Разделение ответственности

| Экран | Что правит |
|---|---|
| Доска «Компания» (без изменений в структуре) | сменные значения: карточки линий (extra_title, время, prep/after на смену, мастера, детектор), расстановка сотрудников (drag&drop) |
| «Производство» → «Линии» | статика и правила: наименование, производительность, тип, дефолты времён, рабочие, возвратные массы, датирование, цвет; добавление/удаление линий |

`lineForm.vue` на доске сокращается до сменных полей: из неё убираются Тип, Возвратные массы, Учитывать в датировании (переезжают в реестр); `title` правится в реестре, на доске остаётся `extra_title`.

### 5.2 Окно «Производство»

- Пункт «Производство» в выпадашке «Реестры» ([toolbar.vue:103](../../../resources/js/vueapp/components/common/toolbar.vue)).
- Модалка `production.vue` (образец — `products.vue`): слева вертикальное меню из 4 пунктов, справа контент.

### 5.3 Вкладки

**«Линии»** — таблица: Наименование, Производительность, Тип (селект), Подготовительное время, Заключительное время, Рабочие, Возвратные массы (селект из справочника), Учитывать в датировании (чекбокс), Цвет.
- Редактирование: inline в ячейках + bulk-edit (выделение строк → «Изменить выделенные» → модалка: заполненные поля применяются ко всем выделенным, пустые не трогаются).
- «Добавить линию» / «Удалить» (удаление запрещено с сообщением, если у линии есть планы).

**«Оборудование»** — таблица: Название, Полное название, Тип (варка/упаковка); добавить/удалить. Radio-кнопки в `plan.vue` и колонка оборудования в `products.vue` берут список из API; константы `hardwares`/`packHardwares` из `dicts.ts` удаляются.

**«Возвратные массы»** — таблица: Название, Тип формулы (фикс/коэффициент), значения (фикс. значение или z/s/k коэффициенты); добавить/удалить.

**«Постоянные величины»** — форма: Интервал варки (мин), Интервал упаковки (мин), Производительность ЗМ, Производительность 2×ЗМ + «Сохранить».

### 5.4 Данные

Новый стор `production.ts`: `hardwares`, `returnTypes`, `settings` — загружаются при открытии окна; используются `plan.vue` (списки оборудования, fallback производительности) и вкладками окна. В отчёте и планировании настройки читает бэкенд.

## 6. Миграции и совместимость

- Все таблицы новые — старая версия приложения их игнорирует; двухэтапная схема не нужна (в отличие от перехода на `type_id = 3`). Миграции + сиды применяются вместе с деплоем новой версии.
- Ссылки сохраняются: `hardware_id` 1–6, `return_type_id` 1–4 — без перемаппинга данных.
- Откат: drop новых таблиц; миграция-чистка обратима (восстановление колонок). `config/lines_defaults.php` удаляется вместе с fallback в `Util::getDefaults` — при откате деплоя возвращаются и старые файлы с конфигом, поэтому откат безопасен.

## 7. Тестирование

### Автотесты (Feature, PHPUnit)

- CRUD `/hardwares`, `/return_types`, `/settings` + защита удаления (используемое оборудование / режим со ссылками).

- Постановка плана: упаковка получает `interval_pack` (15), варка — `interval_boil` (10); изменение `settings` меняет результат.
- Существующий `ProductsPlanControllerTest` — обновить ожидания под +15 у упаковки.

### Ручная проверка

- Сравнение отчёта до/после: отличия только в интервале упаковки.
- Окно «Производство»: все 4 вкладки, bulk-edit на 2+ линиях, добавление/удаление линий, оборудования, режима.
- Доска «Компания»: lineForm сокращён, расстановка сотрудников работает как раньше.
