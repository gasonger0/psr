# Переход на новую систему работы с линиями

Дата: 2026-08-31

Раньше правила использования линий были зашиты в код: ID конкретных линий (`37`, `[8, 9, 10, 11, 12]`, `[14, 17, 18, 20, 24, 25, 41, 51]`, `31`, `20`) и паттерны названий («непрерывная линия», «шоколадная линия», «полуавт», «shot», «телевизор»). Теперь правила — это поля линий и продукции, настраиваемые в интерфейсе.

## Что изменилось

| Было | Стало |
|---|---|
| Сборка ящиков определялась по `line_id == 37` | Роль линии `type_id = 3` («Сборка ящиков») |
| Телевизоры — поиск «телевизор» в названии (линии в бэке — баг, продукции во фронте) | Чекбокс `televisor` у продукции («Справочная информация») |
| Возвратные массы — 4 паттерна названий линий | Дропдаун `return_type` (1–4) в форме линии |
| Датирование — захардкоженные списки линий по категориям | Чекбокс `use_dating` в форме линии |
| Дефолты линий в `config/lines_defaults.php` | `LinesDefaultsSeeder` + таблица `lines_defaults` |

## Нюансы поведения

1. Датирование теперь привязано к линии, а не к категории продукции. Раньше линия 20 датировалась только по суфле, 31 — только по конфетам; теперь датируется вся продукция с отмеченных линий.
2. Телевизор — свойство продукции; заполнено по названиям продукции («телевизор»).
3. Шоколадная линия + категория «конфеты»: раньше `calcReturnMass` падал с `UnhandledMatchError`, теперь корректно не участвует.
4. Линия 37 в отчёте по-прежнему на листе упаковки.

## Гайд по переходу

### Шаг 0. Бэкап

Сделать дамп БД перед миграциями:

```bash
mysqldump -u <user> -p ps > backup_$(date +%F).sql
```

### Шаг 1. Подготовительная миграция (можно заранее, прод продолжает работать)

```bash
php artisan migrate --path=database/migrations/2026_08_31_000000_add_line_rule_fields.php
php artisan db:seed --class=LinesDefaultsSeeder
```

Старая версия приложения на этом этапе работает без изменений: столбцы добавлены, существующие данные (`line_id`, `title`, `type_id`) не тронуты.

### Шаг 2. Деплой новой версии + переключающая миграция

Собрать фронт (`npm run build`), задеплоить код, затем сразу:

```bash
php artisan migrate --path=database/migrations/2026_08_31_000001_set_crate_lines_type3.php
```

Порядок важен: до этой миграции новая версия не считает ящики правильно, а после неё старая версия работать не может.

### Шаг 3. Проверка после перехода

- `php artisan test` — должен пройти `ProductsPlanControllerTest`.
- Линия 37: роль «Сборка ящиков».
- Линии 11/12/14/17/18/41: возвратные массы «Непрерывная линия»; 20 — «Шоколадная линия»; 25 — «Линия-полуавтомат»; 31 — «One-Shot»; 20/31 — «Учитывать в датировании» включено.
- Реестр продукции → «Справочная информация»: у продукции с «телевизор» в названии чекбокс включён.
- Сформировать отчёт и сравнить с отчётом старой версии.

### Шаг 4. Откат

```bash
php artisan migrate:rollback --step=1   # вернёт type_id=2 линии 37
```

Откатить деплой на старую версию кода — она заработает как раньше (новые столбцы игнорирует). Ещё один rollback снимет столбцы.

### Шаг 5. Уборка (после стабилизации)

`config/lines_defaults.php` можно удалить — данные живут в сидере и таблице `lines_defaults` (fallback в `Util::getDefaults` пока оставлен).

## Как работать в новой системе

- **Новая линия**: форма линии → роль (Варка / Упаковка / Сборка ящиков) → при необходимости правило возвратных масс и галочка датирования.
- **Продукция-телевизор**: Реестр продукции → вкладка «Справочная информация» → чекбокс «Телевизор» (шт добавляются в расчёт длительности сборки ящиков).
- Добавление линий с особыми правилами больше не требует правки кода.

## Что осталось на ID/названиях (осознанно, на будущее)

- Накопление `z/s/k` в `TableController` (массивы `[8, 9, 10, 11, 12]`, `[14, 17, 18, 20, 24, 25, 41, 51]`, `31`, `20`).
- Паттерн «one shot» и `line_id == 31` в `plan.vue` (опции упаковки конфет).
- Паттерн «фис машина» в `ProductsPlanController::fixFisMachineConflicts`.
- `type_id` слотов (1–5) — варка/упаковка/глазировка/обсыпка/опудривание.
